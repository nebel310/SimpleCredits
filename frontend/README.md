# Умный кредитный кабинет предпринимателя — фронтенд

Прототип для Альфа-Хак 2026 («Альфа Будущее»), трек «Умный кредитный кабинет предпринимателя». Веб-кабинет клиента и банка: от предварительных шансов до выдачи кредита, с ручной проверкой, запросом документов, сбоями внешних источников и ИИ-помощником.

**Все данные синтетические.** Доступа к ресурсам банка нет: внешние источники (ФНС, БКИ, ФССП, арбитраж, комплаенс), подпись и выдача работают на моках. Платных сервисов нет.

## Запуск

```bash
npm ci
npm run dev          # http://localhost:5173
```

Сборка и Docker:

```bash
npm run build        # статика в dist/
docker build -t credit-cabinet-frontend .
docker run -p 8080:80 credit-cabinet-frontend   # http://localhost:8080
```

Сборка открывается с любого пути (`base: './'`, роутинг через `#/`), поэтому её можно выложить на любой бесплатный статический хостинг для демо.

## Режимы API

| Переменная | Значение | Что происходит |
|---|---|---|
| `VITE_API_MODE` | `mock` (по умолчанию) | Бэкенд имитируется в браузере: статусы, скоринг, источники, роли, события. Состояние в `localStorage`, поэтому заявку видно сразу в нескольких вкладках |
| `VITE_API_MODE` | `http` | Запросы идут на `VITE_API_URL` (по умолчанию `/api`) по контракту из `docs/api-contract.md` |

Фронтенд работает только через интерфейс `CreditApi` (`src/api/client.ts`). Чтобы подключить настоящий бэкенд, достаточно реализовать эндпоинты из `docs/api-contract.md` — экраны менять не нужно. Права, переходы статусов и решения проверяет сервер; фронтенд показывает то, что вернул сервер, и передаёт ключ идемпотентности (`Idempotency-Key`) в действиях, которые нельзя повторять.

## Тестовые аккаунты

Вход — на экране `#/login`, без паролей. В разных вкладках можно войти разными ролями.

| Компания | Сценарий | Роли |
|---|---|---|
| ИП «Компания A» | Стабильные обороты → одобрение без участия банка | владелец, бухгалтер |
| ООО «Компания B» | 8 млн ₽ и совпадение по комплаенсу → комплаенс, андеррайтер, кредитный комитет | владелец, бухгалтер, наблюдатель |
| ООО «Компания C» | Выручка падает → запрос выписки → ручная проверка → решение андеррайтера | владелец, бухгалтер, наблюдатель |
| ИП «Компания D» | Бизнесу 5 месяцев → не хватает данных | владелец |
| ООО «Компания E» | Долг перед налоговой и просрочка 90+ → отказ с советами | владелец, бухгалтер |

Банк: кредитный менеджер (Иванов К. М.), андеррайтер (Петрова Е. В., лимит полномочий 5 млн ₽), комплаенс (Гусев Р. А.).

Демо для жюри: `#/demo/simulator` — пульт источников и сценарии одной кнопкой, `#/demo/mirror` — режим зеркала (клиент и банк на одном экране).

## Сценарии проверки (минимум из ТЗ команды)

1. **Автоматическое одобрение.** Пульт → «Компания A — одобрение без участия банка» → в зеркале клиент принимает предложение и подписывает → «Готовим перечисление» → деньги зачислены.
2. **Встречное предложение.** Пульт → «Компания C…» → клиент загружает выписку, подтверждает распознанные поля, отправляет → менеджер берёт в работу и принимает документ → повторная оценка → андеррайтер выносит встречное предложение → клиент принимает.
3. **Отказ.** Пульт → «Компания E — отказ по стоп-фактору» → у клиента экран решения с причинами и советами.
4. **Запрос документов.** Пульт → «Компания D…» или вручную менеджером из карточки заявки.
5. **Сбой источника и восстановление.** Пульт → «БКИ падает…» → обе стороны видят «Ждём источник. Это не отказ» → на пульте вернуть БКИ в «Работает» → заявка продолжает проверку сама.

Положительные исходы доводятся до подписи и синтетической выдачи. Сбои подписи, выдачи, распознавания, приёма заявок и ИИ включаются на том же пульте.

## Структура

```
src/
  api/
    types.ts        доменная модель — контракт с бэкендом
    catalog.ts      продукты, цели, справочник причин решения
    client.ts       интерфейс CreditApi
    http.ts         реализация по HTTP (для бэкенда команды)
    mock/           мок-сервер: конвейер, скоринг, источники, ИИ, демо-данные
  ai/               ИИ-помощник: кнопка, окно чата, «выделить и спросить»
  layout/           шапки клиента, банка и демо
  pages/client/     главная, мастер (4 шага), заявки, трекер, документы, решение, подписание, кредит
  pages/bank/       очередь задач, карточка заявки, решение андеррайтера
  pages/demo/       пульт источников, режим зеркала
  ui/               компоненты: StatusBanner, DocumentStatus, EmptyState, ErrorState, RoleGuard, ActionButton, пиксельные иконки
  styles/           токены (core-components + наш слой) и стили
docs/
  api-contract.md   эндпоинты для бэкенда
  state-diagram.md  статусы заявки и переходы
  screens.md        экраны, маршруты и что закрыто из постатейного разбора
```

## Дизайн-система

- База — `@alfalab/core-components` (MIT): кнопки, поля, селекты, чекбоксы, радио, переключатели и цветовые токены темы bluetint.
- Наш слой — лайм, фиолетовый для ИИ, пиксельные иконки (одна иконка — одно значение, каждая рисуется одним path).
- Шрифты Unbounded и Onest (OFL) подключены локально через Fontsource — внешних запросов нет.
- Одна красная кнопка на экране — главное действие. Текущий шаг — фиолетовый, пройденные — лаймовые.
- В шапке есть место под официальный логотип (`.logo-slot` в `src/layout/Layouts.tsx`): вставьте файл, полученный от организаторов.

## ИИ-помощник

Кнопка в правом нижнем углу на всех экранах. Три режима: выделить текст и спросить, свободный вопрос, «что мне делать дальше» по шагам. Ответы с источником и датой данных, с учётом роли (наблюдатель не видит документы, бухгалтер не может подписать). Если помощник недоступен, заявка продолжается без него. Решений не принимает. В моке ответы строятся по правилам (`src/api/mock/ai.ts`); в проде на этом месте open-weights LLM на бэкенде (`POST /api/ai/ask`).

## Ограничения прототипа

- Пороги скоринга, ставки и комиссии — демонстрационные, не политика банка.
- Подпись и выдача симулируются, писем и SMS нет — все события в кабинете.
- Только веб, desktop-first; вёрстка адаптируется до ширины телефона.
