# SimpleCredits — фронтенд умного кредитного кабинета

Веб-кабинет предпринимателя и банка для Альфа-Хак 2026 («Альфа Будущее»), трек «Умный кредитный кабинет предпринимателя». Работает с бэкендом из `../backend` строго по `USERFLOW.md`: регистрация → профиль компании → заявка → проверка ЕГРЮЛ/ФНС/БКИ → оценка риска и решение → предложение банка → принятие и модельная выдача. Статус обновляется в реальном времени.

**Все данные синтетические.** Доступа к ресурсам банка нет: госисточники — моки внутри бэкенда, скоринг — open-source модель из `../ml`.

## Запуск

### Всё вместе (Docker)

Из корня репозитория:

```bash
cp .env.example .env
docker compose up -d --build
```

| Сервис | Адрес |
|---|---|
| Фронтенд | http://localhost:5500 |
| Бэкенд (Swagger) | http://localhost:3001/docs |

nginx внутри контейнера фронтенда отдаёт статику и проксирует `/api/*` и WebSocket на `backend:3001`, поэтому CORS не нужен.

### Разработка

Бэкенд и ML должны быть запущены (например, через `docker compose up -d db minio ml backend`).

```bash
cd frontend
npm ci
npm run dev               # http://localhost:5173, /api → http://localhost:3001
```

Если бэкенд на другом адресе — `BACKEND_URL=http://host:port npm run dev`.

### Переменные

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `VITE_API_URL` | `/api` | Адрес API для браузера |
| `BACKEND_URL` | `http://localhost:3001` | Куда проксирует `npm run dev` / `npm run preview` |
| `VITE_ADMIN_EMAIL`, `VITE_ADMIN_PASSWORD` | `admin@admin.com` / `admin` | Кнопка «Войти как банк». Должны совпадать с `ADMIN_EMAIL` / `ADMIN_PASSWORD` бэкенда |

## Вход

- **Регистрация и вход** по email и паролю (`/auth/register`, `/auth/login`, JWT). Access-токен продлевается через `/auth/refresh`; если не вышло — сессия завершается.
- **Демо-аккаунты** — одна кнопка. При первом входе аккаунт регистрируется и получает синтетический профиль через `PATCH /auth/me`. ИНН подобраны так, что ответы мок-ЕГРЮЛ и мок-БКИ ведут к нужному сценарию: реквизиты в профиле — как в ЕГРЮЛ, кредитная история — как в БКИ (банк берёт её оттуда). Исход — то, что реально решают модель и правила банка:

| Аккаунт | Сценарий | Статус · тип результата | Что дальше |
|---|---|---|---|
| A · ИП Компания 9986 | Стабильный бизнес, оборотный кредит 3 млн | `confirmed` | «Принять предложение» → «Подтвердить и оформить» → договор SC-… |
| B · ООО Компания 2785 | Кредитная линия 20 млн при выручке 30 млн | `different` · `COUNTER_OFFER` | Банк предлагает 15 млн; принять или отказаться |
| C · ООО Компания 7752 | Риск в пограничной зоне | `different` · `MANUAL_REVIEW` | Ждёт решения сотрудника банка; принимать нечего |
| D · ИП Компания 7622 | Продукт не выбран, оборудование 500 тыс | `different` · `ALTERNATIVE_PRODUCT` | Банк подобрал лизинг; принять или отказаться |
| E · ООО Компания 1178 | Текущая просрочка в БКИ | `declined` (`CURRENT_PAST_DUE`) | Причина и советы, новая заявка |
| Банк · администратор | Роль `admin` | — | Все заявки, «Ждут проверки», решение по ручной проверке, статистика, модель |

Статус `failed` появляется, когда ML недоступен: бэкенд отвечает 502/504 и присылает номер сохранённой заявки. Фронтенд открывает её карточку с кнопкой «Повторить проверку» — заново подавать не нужно.

## Путь клиента после решения

- **Исходы различаются.** `different` уточняется типом результата: «Подобрали продукт» (банк выбрал сам), «Подобрали другой продукт», «Предлагаем другие условия», «Нужна дополнительная проверка» — последнее не оффер, кнопки «Принять» нет.
- **Над трекером** — текущий статус, пояснение и «Что дальше». Этапы: «Заявка отправлена → Данные получены → Оценка завершена → Решение готово → Предложение принято → Кредит выдан».
- **Предложение** — продукт, сумма, срок, ставка по оценке риска внутри диапазона продукта, платёж, всего выплатить, переплата. «Что если?» пересчитывает платёж и остаток денег в месяц при другой сумме и сроке (условия банка не меняются).
- **Что повлияло на решение** — категория риска, главные причины, до 5 факторов, посчитанных по данным заявки, и советы «что делать дальше». Балл, PD, грейд и все факторы модели видит только банк.
- **Принятие и выдача** — «Принять предложение» → «Подтвердить и оформить» → номер модельного договора. Выдача синтетическая: реальных денег и документов нет.
- **Сбой ML** — «Повторить проверку» по той же заявке.

## Чего нет

Мастера с черновиками, запроса документов, подписания, графика платежей, ролей бухгалтера и наблюдателя. Фронтенд показывает только то, что умеет бэкенд.

Что покрыто, что найдено и исправлено — `docs/testing.md`. Проверка скоринговой модели на реалистичных данных — `docs/model-check.md` и `scripts/model-check.py`.

## Структура

```
src/
  api/
    types.ts      типы из Pydantic-схем бэкенда
    http.ts       fetch, Bearer-токен, продление сессии, ошибки {detail}
    index.ts      все эндпоинты бэкенда
    session.ts    токены и пользователь (sessionStorage)
    ws.ts         WebSocket /ws/applications с переподключением
  lib/            вход, демо-аккаунты, подписи статусов и исходов, правила каталога (rules.ts), форматирование
  layout/         шапки кабинета клиента и банка
  pages/client/   главная, профиль, продукты, заявка, список заявок
  pages/bank/     все заявки и статистика
  pages/shared/   карточка заявки (общая для клиента и банка): предложение и «Что если?»,
                  объяснение решения, решение банка
  ui/             компоненты на @alfalab/core-components, пиксельные иконки
  styles/         токены и стили
e2e/              сценарии Playwright
scripts/          проверка скоринговой модели
```

## Дизайн-система

- База — `@alfalab/core-components` (MIT): кнопки, поля, селекты, чекбоксы, радио и цветовые токены.
- Наш слой — лайм для пройденных шагов, пиксельные иконки (одна иконка — одно значение).
- Шрифты Unbounded и Onest (OFL) подключены локально — внешних запросов нет.
- Одна красная кнопка на экране — главное действие.
- Знак SimpleCredits — пиксельное сердце с искрой (`src/ui/Logo.tsx`), он же иконка вкладки (`public/favicon.svg`).

## Заметки для бэкенда

- `GET /applications` и `GET /admin/applications` отдают заявки от старых к новым. Фронтенд собирает все страницы и показывает новые сверху.
