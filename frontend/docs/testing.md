# Тестирование фронтенда

## Как запускать

```bash
cd frontend
npm test                                   # юнит-тесты (Vitest), бэкенд не нужен
npm run test:e2e                           # e2e (Playwright) против docker compose: http://localhost:5500
E2E_BASE_URL=http://localhost:5173 npm run test:e2e   # против npm run dev
```

Для e2e должен быть запущен весь стек (бэкенд, ML, база). Браузер для Playwright ставится один раз: `npx playwright install chromium`. Тесты не зависят от того, что уже лежит в базе: регистрации идут на новые email, демо-аккаунты переиспользуются.

## Что ещё проверено вручную

- Все экраны на ширине телефона — без горизонтальной прокрутки, ошибок в консоли нет.
- Ответы бэкенда на крайние значения (пустой пароль, повтор имени, даты в будущем, сумма 0 и 1 ₽, заявка от админа) — по ним добавлены проверки на фронте.
- Отказ ML (502): заявка сохраняется, открывается её карточка; «Повторить проверку» при выключенном ML — понятная ошибка, после запуска ML — решение по той же заявке, в истории видны обе попытки. Истёкший токен — сессия продлевается сама.
- Все пять демо-сценариев и решение банка — по скриншотам на 1440 px и 375 px.
- Модель — на 14 реалистичных профилях, 4 примерах из `examples/` и 11 сериях «меняем один фактор»: `docs/model-check.md`.

## Найдено и исправлено

1. Минимальная сумма микрозайма 50 000 ₽ показывалась как «0,1 млн ₽» — ошибка округления.
2. Подсказка к полю суммы была в миллионах с запятой, а поле принимает целые рубли — теперь подсказка в рублях.
3. «до 24 месяца» → «до 24 месяцев».
4. При регистрации можно было задать пароль из одного символа — теперь не короче 6.
5. Дата регистрации компании и отчётный период могли быть в будущем.
6. Без выбора продукта можно было отправить заявку на 1 ₽ — теперь сумма и срок в границах каталога (50 000 ₽ – 50 млн ₽, 1–60 месяцев).
7. Факторы модели с общим описанием «Фактор повышает риск» показывались с техническим именем признака — теперь понятное название; для данных, которых нет в заявке, есть пометка. Техническое имя видно только банку.
8. В кабинете банка на телефоне показатели шли по одному в строку.
9. В каталоге ставка кредитной линии 17,5% показывалась как «18%» — округление до целого.
10. Тосты появлялись слева внизу и перекрывали кнопку «Сохранить профиль» — теперь справа и не перехватывают клики.
11. При первом демо-входе экран входа уводил в кабинет раньше, чем профиль был заполнен; после регистрации клиент на мгновение попадал на главную.
12. Клиент видел балл, PD и грейд, а среди факторов — признаки, которых нет в заявке. Теперь у клиента категория риска и подтверждённые факторы, детали — у банка.
13. Ручная проверка выглядела как готовое предложение; после сбоя ML предлагалось подать заявку заново (вторая заявка).

## Решения

- **Админ не подаёт заявки.** По USERFLOW §2 роль admin смотрит заявки и статистику, а заявки подаёт user. У админа нет профиля компании, поэтому бэкенд всё равно ответит 400 «Профиль компании не заполнен».
- **Обработка занимает доли секунды — это не заглушка.** Подробно — в `docs/model-check.md`.

## Замечания для бэкенда

- Списки заявок отдаются от старых к новым — фронтенд сортирует сам.
- Пустой пароль, повторяющиеся имена, даты в будущем, сумма 0 ₽, долгое переподключение к ML после перезапуска, закомментированный `.env.example` — исправлены в бэкенде.
