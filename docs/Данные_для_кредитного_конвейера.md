# Данные для кредитного конвейера МСП

Документ описывает, какие данные можно получить и использовать в кредитном процессе малого и микробизнеса: от клиента, из банковского обслуживания, государственных сервисов, бюро кредитных историй, сервисов проверки бизнеса, учётных систем и альтернативных источников.

Для хакатонного прототипа все внешние источники заменяются моками, стабами или синтетическими данными. Реальные интеграции не требуются.

---

## 1. Принципы работы с данными

1. **Минимальная достаточность.** Запрашиваем только то, что влияет на кредитное решение или клиентский путь.
2. **Согласие.** Персональные данные, кредитная история, банковская и налоговая тайна требуют согласия клиента.
3. **Прозрачность.** Клиент должен понимать, какие данные используются и как они влияют на предложение.
4. **Проверяемость.** Для каждого признака фиксируем источник, дату получения и качество.
5. **Разделение слоёв.** Сырые данные → нормализованные признаки → скоринг → policy-решение.
6. **Безопасность.** Маскирование ПДн, разграничение доступа, аудит, сроки хранения.
7. **Синтетика в прототипе.** Реальные клиентские данные не используются, интеграции имитируются.

## 13. Что стоит показывать в демо

1. Клиент заполняет заявку и даёт согласия.
2. Система подтягивает данные из моков ЕГРЮЛ, БФО, банка и БКИ.
3. Показывает клиенту, какие данные использованы.
4. Считает риск и объясняет причины.
5. Предлагает условия, отказ или ручное рассмотрение.
6. Показывает, какие данные повлияли на решение.
7. Доводит сценарий до моделируемой выдачи.

## 16. Итог

Для MVP достаточно пяти групп данных:

1. Заявка клиента.
2. ЕГРЮЛ/ЕГРИП.
3. Финансовая отчётность.
4. Банковские обороты.
5. Кредитная история и внутренняя история банка.

Этого хватает, чтобы построить сквозной кредитный путь, скоринг, объяснение решения и policy-движок. Остальные источники добавляют глубину, но не должны ломать основной сценарий и не должны требовать платных API или реальных интеграций.
