# Тестовые сценарии

Как поднять стек — в [README](../README.md#быстрый-старт). Демо-аккаунты входят одной кнопкой на экране входа, администратор — `admin@admin.com` / `admin`.

## Сценарии для ручной проверки

| № | Сценарий | Шаги | Ожидаемый результат | Автотест |
|---|---|---|---|---|
| 1 | Одобрение и оформление | Войти как A → «Новая заявка» → «Отправить заявку» → «Принять предложение» → «Подтвердить и оформить» | «Заявка одобрена», условия со ставкой и платежом; после принятия — «Предложение принято»; после подтверждения — «Кредит оформлен», договор `SC-ГГГГММДД-XXXXXX`, трекер пройден целиком | e2e `scenarios.spec.ts` (A); бэкенд `e2e/test_deal.py` |
| 2 | Встречное предложение | Войти как B → отправить заявку (кредитная линия 20 млн) | «Предлагаем другие условия»: 15 000 000 ₽ вместо 20 000 000 ₽, причина «сумма больше 60% годовой выручки»; можно принять или отказаться | e2e `scenarios.spec.ts` (B); бэкенд `e2e/test_outcomes.py` |
| 3 | Ручная проверка и решение банка | Войти как C → отправить заявку. Выйти, войти как Банк → «Ждут проверки» → заявка C → «Одобрить с другой суммой», сумма, комментарий → «Сохранить решение». Войти как C | У клиента сначала «Нужна дополнительная проверка» без кнопки «Принять». После решения банка — «Предлагаем другие условия», блок «Решение сотрудника банка» с комментарием, кнопка «Принять предложение» | e2e `scenarios.spec.ts` (C); бэкенд `e2e/test_bank_decision.py` |
| 4 | Банк подбирает продукт | Войти как D → оставить «Подобрать за меня» → отправить | На форме видно «Подойдёт: Лизинг оборудования»; в карточке «Подобрали продукт», подпись «подобран банком» | e2e `scenarios.spec.ts` (D); бэкенд `e2e/test_product_rules.py` |
| 5 | Отказ с объяснением | Войти как E → отправить заявку | «Банк отказал», причина «сейчас есть просрочка по кредитам», блок «Что делать дальше», кнопка «Новая заявка» | e2e `scenarios.spec.ts` (E); бэкенд `e2e/test_bki_scoring.py` |
| 6 | Нет подходящего продукта | Своя компания → «Подобрать за меня» → сумма или цель, под которые нет продукта | На форме — «Под эти условия продукта нет». Если отправить — отказ «Нет подходящего продукта» с советом изменить параметры | бэкенд `e2e/test_product_rules.py`; фронт `rules.test.ts` |
| 7 | Сбой ML и повтор | `docker compose stop ml` → отправить заявку → `docker compose start ml` → «Повторить проверку» | Заявка сохранена и открыта: «Проверка не завершилась», трекер остановлен на оценке. Повтор при выключенном ML — понятная ошибка. После запуска ML — решение по той же заявке, в истории обе попытки | бэкенд `e2e/test_retry_idempotency.py`; проверено вручную |
| 8 | Без дублей | Дважды быстро нажать «Отправить заявку» или повторить запрос с тем же `Idempotency-Key` | Создаётся одна заявка | бэкенд `e2e/test_retry_idempotency.py`; фронт `api/index.test.ts` |
| 9 | Регистрация и профиль | Регистрация → ИНН → «Найти в ЕГРЮЛ» → финансы → «Сохранить профиль» → «Подать заявку» | Реквизиты подставились из ЕГРЮЛ, кредитная история — из БКИ (только чтение); после первого сохранения — переход к заявке | e2e `profile-apply.spec.ts`; бэкенд `integration/test_mock_router.py` |
| 10 | Проверки ввода | Пароль короче 6 символов, пароли не совпадают, повторный email, дата регистрации в будущем, сумма 0, ИНН неправильной длины | Понятные ошибки у полей, данные не уходят | e2e `auth.spec.ts`, `profile-apply.spec.ts`; бэкенд `e2e/test_validation.py` |
| 11 | Форма заявки | Войти как B → «Новая заявка» | Сегмент «малый бизнес» определён банком; «Микрозайм» недоступен с причиной; суммы и сроки вне границ продукта не отправляются; платёж показан заранее | e2e `profile-apply.spec.ts` |
| 12 | Права доступа | Клиент открывает `#/bank`, чужую заявку, чужой файл; банк открывает кабинет клиента | Клиента не пускает в кабинет банка, чужие заявки и файлы — «не найдено»; банк не видит кнопок клиента | e2e `roles.spec.ts`; бэкенд `e2e/test_security.py`, `integration/test_files_router.py` |
| 13 | Выход из аккаунта | Выйти и повторить запрос или WebSocket со старым токеном | Запрос отклонён, WebSocket закрывается с кодом 4401 | бэкенд `e2e/test_security.py`, `e2e/test_ws_flow.py` |
| 14 | Живые обновления | Отправить заявку и следить за экраном | Этапы «Заявка отправлена → Данные получены → Оценка завершена → Решение готово» двигаются по событиям WebSocket; в сообщениях клиенту нет балла и PD | бэкенд `e2e/test_ws_flow.py` |
| 15 | Кабинет банка | Войти как Банк | Статистика по статусам, типу результата, продуктам и грейдам; фильтр «Ждут проверки»; в карточке — балл, PD, грейд и все факторы модели | e2e `roles.spec.ts`; бэкенд `e2e/test_admin_flow.py` |
| 16 | Телефон | Открыть экраны на ширине 375 px | Нет горизонтальной прокрутки и ошибок в консоли | e2e `smoke.spec.ts` |
| 17 | Старая база | Поднять новую версию на базе с заявками прошлой версии | Бэкенд добавляет новые колонки, старые заявки открываются, им проставлен тип результата | бэкенд `unit/test_database_migrations.py`; проверено на живом Postgres |
| 18 | Повторный кредит | Войти как A → оформить кредит → подать ещё одну заявку | В карточке новой заявки «Платежи по кредитам в месяц» включают уже выданный кредит, строка «Из них кредиты нашего банка»; риск и ставка выше, чем в первый раз | бэкенд `e2e/test_bank_credits.py` |

## Автотесты

| Часть | Что | Сколько | Как запустить |
|---|---|---|---|
| Бэкенд | unit, integration, e2e на SQLite в памяти | 393 | `cd backend && uv sync && uv run pytest` |
| Фронтенд | юнит-тесты: правила каталога, подписи исходов, трекер, API-клиент, демо-данные | 102 | `cd frontend && npm ci && npm test` |
| Фронтенд | e2e в браузере против поднятого стека | 26 | `cd frontend && npx playwright install chromium && npm run test:e2e` |
| ML | данные, признаки, обучение, политика, скоринг, gRPC | 29 + 1 пропущен | `cd ml && pip install -e ".[dev]" && pytest` |

Подробности по фронтенду — [frontend/docs/testing.md](../frontend/docs/testing.md), по ML — [ml/README.md](../ml/README.md#тесты), проверка модели на реалистичных профилях — [frontend/docs/model-check.md](../frontend/docs/model-check.md).

E2E по умолчанию ходят на `http://localhost:5500` (docker compose); для `npm run dev` — `E2E_BASE_URL=http://localhost:5173 npm run test:e2e`.
